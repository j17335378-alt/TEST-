# الأستوديو (إعادة البناء)

## سبب الأعطال السابقة
الأستوديو القديم كان يحتفظ بمسارات (Uri) الملفات المختارة في قائمة داخل الذاكرة فقط، ولا ينسخ أي ملف، ولا يعرض صوراً مصغّرة (كان يعرض اسم الملف كنص)، ولا يحفظ شيئاً. لذلك تظهر رسالة «تم الاختيار» ثم تختفي الملفات عند أي إعادة تشغيل.

> ملاحظة: التطبيق الحالي واجهة Android أصلية (NativeHomeActivity) ولا يستخدم WebView، لذلك لا حاجة إلى JavaScript Bridge.
> الحل كله بـ Java أصلية، وهو الأنسب للبنية الحالية. `index.html` و`MainActivity` لم يُمسّا.

## التخزين
كل شيء داخل مساحة التطبيق الخاصة `files/studio/`:

| المسار | المحتوى |
|---|---|
| `media/` | الصور والفيديوهات والملفات (تُنسخ بالتدفق على دفعات 64KB، بلا Base64) |
| `thumbs/` | مصغّرات JPEG مخزّنة مؤقتاً |
| `notes/<id>.txt` | نص كل ملاحظة في ملف مستقل (بلا حد للطول) |
| `index.json` | البيانات الوصفية فقط (المجلدات، الدفاتر، التصنيفات...) تُكتب بشكل ذري + نسخة `.bak` |

- لا صلاحيات إضافية: الاختيار عبر `ACTION_OPEN_DOCUMENT` (منتقي أندرويد الأصلي).
- الملفات الخاصة تُفتح في تطبيقات أخرى عبر `StudioFileProvider` (غير مُصدَّر، بصلاحيات مؤقتة).

## الملفات
- جديدة: `StudioStore`, `StudioMedia`, `StudioContext`, `StudioGrid`, `StudioMediaSection`, `StudioScreen`, `MediaViewerScreen`, `MedicalScreen`, `NoteEditorScreen`, `StudioFileProvider`.
- معدّلة: `NativeHomeActivity` (ربط الأستوديو فقط)، `AndroidManifest.xml` (تسجيل المزوّد)، `app/build.gradle` (رقم الإصدار).
